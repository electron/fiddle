## Lucent

Fiddle with a glass finish, in Electron's colours. The chrome is navy glass, the code sits on a solid sheet of Electron navy, and cyan means action.

 ForElectron Fiddle's renderer, built in React
 CoversTokens, native materials, the main window, 60 components, flows, accessibility
 AppearanceDark and light, following the OS. Dark is the hero.
 FontsInter (variable, with optical sizes) and Commit Mono. Both SIL Open Font License.

- Build the window to Window anatomy, then the flows, then components.

- The live specimens are the prototype. Where a table and a specimen disagree, the table wins.

Live specimen. Press Run: renderer.js gets an error badge, the error shows under its line, and the console logs it. The split button at the right of the tab row opens a second pane. The coloured backdrop stands in for the user's desktop, and the small glass window stands in for the fiddle's own window, which in the app is a real Electron window.

## Principles and rules
Four ideas carry the whole system. When a case isn't covered here, decide it by these.

- Glass for chrome, paper for workTitle bar, sidebar, status bar, menus and floating panes are translucent. Code, the console and anything you read at length sit on the solid sheet.

- Cyan is the actionRun is a cyan capsule with a navy label, and cyan marks focus and selection. In light it flips to navy with a cyan label. Red means running or broken, nothing else.

- Layers, not linesSurfaces separate by depth, blur and a lit edge. Hairlines are 0.5px and appear only where rows need them.

- Chrome floats in capsulesToolbar controls gather into glass capsules. Everything inside the sheet uses continuous-corner rectangles.

### Do

- Take every value from a token. If a value is missing, add a token rather than a literal.

- Keep one editor by default. The split is opt-in, from the tab row or ⌘\.

- Use sentence case everywhere: buttons, menus, section heads, the status bar.

- Keep corners concentric: an inner radius is the outer radius minus the inset.

- Let the OS draw window corners, shadows and the window controls.

### Don't

- Put glass behind code, the console, dialogs' body copy or long text.

- Use cyan for decoration, or red for anything that isn't running or broken.

- Add gradients. The only ones are the primary sheen and the assist ring.

- Use uppercase labels, borders between panes, or 1px dividers.

- Stack a blurred overlay on another blurred surface without checking legibility.

## Glass on real windows
In the prototype the glass blurs a painted backdrop. In the app, the backdrop is the user's own desktop, which the page can't see. So the frosting comes from the OS, and Lucent paints a thin tint on top.

 | 
 | Platform | Material under the chrome | Title bar | Notes

 | macOS | vibrancy: 'under-window' | titleBarStyle: 'hiddenInset' | Centre the traffic lights in the 56px bar (trafficLightPosition) and keep 80px clear on the left. Use visualEffectState: 'followWindow' so the glass dims when the window is inactive.

 | Windows 11 | backgroundMaterial: 'acrylic' | titleBarStyle: 'hidden' + titleBarOverlay | The overlay draws the caption buttons on the right; keep 140px clear and move Publish and Settings left of it. Set the overlay's symbolColor to ink and update it when the appearance changes.

 | Linux, or no material | none | native frame or hidden + overlay | Add lu-no-material to <html>. The tokens swap every material for its opaque fallback.

The page background must be transparent for the material to show: html, body { background: transparent }, with the chrome painted in --lu-material-chrome and the sheet in --lu-surface. Mark the title bar as a drag region (-webkit-app-region: drag) and every control in it as no-drag.

Copy
// Main process: the window Lucent expects. Verify each option on each OS.

 // titleBarOverlay { color: '#00000000', symbolColor: ink, height: 56 }
})

Fallbacks are part of the design, not a degraded mode. With Reduce transparency on (prefers-reduced-transparency: reduce), on Linux, or when a material fails, the chrome becomes --lu-window and overlays become --lu-surface-raised. It should still look finished: same layout, same capsules, just opaque.

Test chrome text on hostile desktops. Try a black wallpaper and a saturated photo in both appearances. If ink-muted on the title bar or sidebar drops below 4.5:1, raise the chrome tint's alpha from 0.62 toward 0.78. Don't darken the text.

Glass on glass. Chromium doesn't blur an element through another element that already has a backdrop filter. Menus and popovers that open over the chrome therefore see only the tint, which is why material-overlay is 86 to 90% opaque: it stays legible whether or not the blur has anything to sample.

## Motion
One curve for everything: a quick start and a long, soft landing. Things settle rather than bounce. Colour changes are fast; anything that moves takes a little longer.

cubic-bezier(.32, .72, 0, 1)

A press takes 220ms, a colour change 150ms. Nothing in the app loops except spinners.

### Behaviour

 | One editor by default | Tabs for main.js, preload.js, renderer.js, index.html and styles.css. The process label (Main process, Preload, Renderer) sits at the right of the tab row, in ink-faint.

 | Split | The columns button at the right end of the tab row, or ⌘\. Opens a second pane beside the current one showing renderer.js, or main.js when renderer.js is current. The tab row keeps driving the left pane. Press again to close. Tooltip: "Split editor ⌘\" or "Close split".

 | Pop-out | Each pane header in split view carries a pop-out action. A popped-out file opens in its own window with the same chrome and sheet, and its tab shows a small window glyph until it's docked back.

 | Sidebar | Groups files by process: Main process, Preload, Renderer, then Packages with an "Add a package" field. Clicking a file opens its tab. The sidebar button in the title bar hides it; the sheet then runs to 8px from the left edge too.

 | Resizing | Drag the sidebar edge (200 to 320px) and the top of the console (96px to half the sheet). Dividers are invisible until hover, then show a 2px cyan line.

### States

 | Hover | Ghost and icon buttons take fill. Secondary buttons take button-hover. Rows on the sheet take hover at 55 to 60%. Toolbar buttons take capsule-hover.

 | Pressed | Scale to 0.965 over 220ms; fills go to fill-strong. Primary darkens: action mixed 14% toward black, sheen removed.

 | Selected | Tabs: hover fill, ink text. Sidebar rows: chip with shadow-lift, icon in accent. Menu items: weight 500, no fill. Segments: thumb with shadow-lift.

 | Focus | Buttons, tabs, switches, checkboxes: 3px outline in accent at 70%, 1px offset (inset 3px inside lists and tab rows). Fields and open selects: border turns accent plus a 3.5px ring of accent at 26%.

 | Disabled | 40% opacity. No hover, no press. Keep the tooltip so people can learn why.

 | Invalid | Field border spark, focus ring spark at 22%, message below in spark.

### Beyond contrast

 | Keyboard | Everything is reachable by Tab. Tabs, trees, menus and segmented controls use arrow keys inside, one Tab stop each. ⌘R runs and stops, ⌘\ splits, ⌘↵ sends the assist prompt.

 | Targets | 24px minimum (tab-row icon buttons). Toolbar controls are 30 to 36px.

 | Reduce motion | Drop scale, travel and blur-in. Keep colour changes and spinners.

 | Reduce transparency | Materials go opaque (see Glass on real windows). Nothing else changes.

 | Increase contrast | Under prefers-contrast: more, draw hairlines at 1px in line-strong and raise the chrome tint to 0.9.

 | Announcements | The Run button announces "Ready to run", "Starting", "Running Electron 43.0.0". New console errors announce once, politely.

## Acceptance checklist
Walk this in dark and light, on macOS and Windows, before calling it done.

- Tokens. No colour, radius, shadow or duration literal in component styles. Grep for # and rgba( outside the token file.

- Material. The desktop shows through the title bar, sidebar and status bar; the sheet is fully opaque; the window corners and shadow are the OS's.

- Fallback. With Reduce transparency on, and on Linux, the chrome is opaque and the app still looks finished.

- Title bar. 56px, drag region works, traffic lights centred (macOS) or caption buttons clear (Windows), capsule centred in the window.

- Default layout. One editor with five tabs, the process label at the right, console 160px, status bar 32px.

- Split. The button and ⌘\ open and close a second pane; the tooltip text matches the state.

- Run. All four states, fixed width, correct announcements, the Running pill in the status bar.

- Errors. Tab badge, sidebar pill, error line, lens aligned to the code column, console row with a working link.

- Menus. The version menu opens above the editor, sizes to its labels, and is readable over the chrome.

- Corners. Squircles where supported, round elsewhere, concentric everywhere (menu 17 = item 12 + padding 5).

- Hairlines. 0.5px, only between rows, above the console and under the tab row.

- Type. Inter with optical sizes and the two features; Commit Mono in the editor and console; sentence case.

- Focus. Visible on every control, never clipped by a parent's overflow.

- Contrast. The table above holds; chrome text still passes over a black and a saturated wallpaper.
